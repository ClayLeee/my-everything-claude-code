# E2E Run — Execute Tests + Error Classification + Report

Run existing E2E tests, classify failures, and generate dual reports. This command only classifies and reports; it does not change tests or test data.

All output must be in **繁體中文**. `$SKILL_DIR` below is `${CLAUDE_PLUGIN_ROOT}/skills/e2e-testing`.

## Step 1: Locate Spec File

- If `$ARGUMENTS` provided, use it as the spec path
- If no argument, look for spec files in `tests/e2e/` (excluding `pages/`, `auth/`, `fixtures/`) and ask the user which to run
- If the spec file does not exist, suggest `/e2e:analyze` → `/e2e:plan` → `/e2e:create` instead

## Step 2: Verify Dev Server

Check if the dev server URL is reachable (from `playwright.config.*` `use.baseURL`, else the dev script / framework default — see SKILL.md § Running Tests). If not:
- Try the dev command (`{run} dev`) in the background from the directory that holds the project's `package.json`, or
- Inform the user that the dev server needs to be running

## Step 3: Execute Tests

Run from the directory that holds the project's `package.json`, with the project's package manager runner (`{run}` / `{exec}` from the lockfile — see SKILL.md § Running Tests):
```bash
E2E_REPORT_NAME={page-name} {run} test:e2e -- {spec-path}
```

If no dedicated E2E script exists: `E2E_REPORT_NAME={page-name} {exec} playwright test {spec-path}`.

## Step 4: Classify Failures

If any test failed, read `$SKILL_DIR/references/error-discrimination.md` and classify each failure with its decision flow: API errors as ENVIRONMENT (entity state), RECOVERABLE (duplicate / invalid format) or NON-RECOVERABLE; element errors as LOCATOR_MISMATCH or TIMING; page loading errors as NON-RECOVERABLE. Do not fix anything here; count failures by type for the next-step suggestion.

## Step 5: Generate Dual Reports

1. **HTML report** — Already generated by Playwright at `playwright/reports/{page-name}/`
2. **Markdown report** — Generate via `generate-report.js`:

```bash
echo '{"pageName":"{page-name}","pageNameZh":"{page-name-zh}","testDate":"YYYY-MM-DD","testUrl":"{test-url}","testAccount":"{account}","describeGroups":[...],"outputDir":"playwright/reports/{page-name}"}' | node $SKILL_DIR/scripts/generate-report.js
```

Include test results summary (pass/fail/skip counts), per-failure error classification, and recommended actions for each failure type in the JSON input.

## Step 6: Completion

Tell the user:

```
✅ 測試執行完畢。
📄 報告：
   - HTML: playwright/reports/{page-name}/
   - MD: playwright/reports/{page-name}/test-report.md
```

If there are failures, summarize by type and suggest next command:

```
⚠️ {N} 個測試失敗：
   - {X} 個 LOCATOR_MISMATCH（data-testid 找不到或不匹配）
   - {Y} 個 TIMING（元素未出現或 timeout）
   - {Z} 個 ENVIRONMENT（實體狀態異常）
   - {W} 個 NON-RECOVERABLE（伺服器錯誤/權限問題）
👉 執行 /e2e:maintain 自動修復（含 MCP debug loop）
```

Omit categories with 0 count. Adjust the suggestion based on failure types:
- LOCATOR_MISMATCH / TIMING dominant → suggest `/e2e:maintain`
- ENVIRONMENT dominant → suggest fixing entity state via UI, then `/e2e:run` again
- NON-RECOVERABLE dominant → suggest checking server logs or test assumptions
