⚠️ OpenSpec + Superpowers workflow ACTIVE. Overrides superpowers/opsx defaults where conflicting.

1. **Phase 0 Triage before any task.** Read `openspec/specs/<cap>/spec.md`, classify code-only/new-feature/spec-patch/spec-rewrite (retro-doc only when the user says the code already exists). code-only without conflict → announce in one line and proceed. spec-patch → one stop at the spec diff. new-feature/spec-rewrite/retro-doc or any spec conflict → STOP, routing in the same `AskUserQuestion` as design questions. Any plain go-ahead (繼續/ok/yes) confirms; never require exact phrases. Ambiguous → spec-heavy, except copy/style/no-behavior refactor/dep bump/test-only = code-only.
2. **Never edit `openspec/specs/` by hand; it changes only via archive.** spec-patch (spec misdescribes behavior that is not changing; any behavior change is new-feature/spec-rewrite): an unarchived change **related to this code change** (its delta covers the affected Requirements, or this is its own work — same capability alone is not enough) → edit it directly; none → new change with all four OpenSpec files (proposal, design, delta spec, tasks; no Superpowers docs). Never edit unrelated changes; unclear → ask. Related but uncommitted and not created by this session = another session's work in progress → ask first. Diff first, `openspec validate <change> --strict` after.
3. **No add/commit/push/stash/merge/rebase in any phase — code or docs — until the user approves pushing this work after the Phase 6 report** (project CLAUDE.md or skills don't count). Then in one go: if the project has `.claude/push-checks.json`, the push-checks tool (it skips when only the project's `skipWhenOnly` paths changed) → commit (stage only this session's files/hunks, never `-A`; body names `OpenSpec: <change>`) → push. Read-only status/diff/log OK anytime.
4. **No prod code until 6 artifacts exist (new-feature/spec-rewrite):** `docs/superpowers/{specs,plans}/<date>-*.md` + `openspec/changes/<name>/{proposal,design,tasks}.md` + `openspec/changes/<name>/specs/<cap>/spec.md`. No `RENAMED` blocks in deltas (REMOVED + ADDED). Guardrail covers this task's change only — other sessions' unarchived changes never block, and are never edited or archived here.
5. **Iron Law (Phase 4):** failing test before any production code. Parallel agents when plan tasks are independent.
6. **Phase 5:** run the actual user scenario; UI with Playwright, asserting on snapshot/network, at most one screenshot per scenario. Needs sign-in → open the sign-in page, tell the user what account it needs (a role/permission only if the scenario depends on one), wait (never handle passwords). Still can't run → `DEFERRED(L2: <reason>)` + list under L2 未驗 with manual steps. No "should work".
7. **Phase 6 Align & Finish (all paths; = "對齊並 archive"):** drift-check diff vs specs/tests (code-only that changed behavior → upgrade); archive only if a change exists — never create one just to archive; a patched existing change with open work stays unarchived; before archive no bare unchecked tasks; after, confirm delta landed in main spec, Purpose ≠ TBD, `openspec validate --specs --strict`; report with commit suggestions.
8. **Skill 1% rule:** even 1% chance a skill applies → invoke before any action.
